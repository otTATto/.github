# Security Policy

This policy applies to all my repositories, unless a repository has its own `SECURITY.md`.

## Reporting a Vulnerability

> [!CAUTION]
> **Please DO NOT report security vulnerabilities through PUBLIC issues, pull requests, or discussions.**

Instead, report them privately in one of the following ways:

- **GitHub private vulnerability reporting:** Open the **Security** tab of the repository and click **Report a vulnerability**. This button appears only when the feature is enabled for the repository.
- **Email:** Send an email to [hi@tato.bio](mailto:hi@tato.bio).

Please include as much of the following as you can:

- The affected repository, and the version or commit
- Steps to reproduce the issue
- The impact, and how an attacker could exploit it

> [!NOTE]
> You can write your report in either English or Japanese.

## What to Expect

These are personal projects that I maintain in my spare time. I will do my best to:

- Acknowledge your report as soon as I can
- Keep you updated on the progress of the fix
- Credit you when the fix is published, unless you prefer to stay anonymous

Please give me a reasonable amount of time to fix the issue before you disclose it publicly.

## Supported Versions

Only the latest release receives security fixes. For projects without releases, only the default branch does.
